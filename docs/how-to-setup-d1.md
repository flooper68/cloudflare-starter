# How To Setup The D1 Database

The web app stores its data, including Better Auth's users and sessions, in [Cloudflare D1](https://developers.cloudflare.com/d1/) (SQLite). The schema is Drizzle; migrations are plain SQL generated by `drizzle-kit` and applied by Wrangler. Only the web worker has the `DB` binding.

| What       | Where                                                                                                                                   |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| Schema     | [packages/features/src/db/schema/](../packages/features/src/db/schema/)                                                                 |
| Migrations | [packages/features/migrations/](../packages/features/migrations/)                                                                       |
| Binding    | `DB` in [apps/web/wrangler.jsonc](../apps/web/wrangler.jsonc), one database per environment                                             |
| Client     | `createDb(env.DB)` from `@cloudflare-starter/features`, cached per isolate in [apps/web/src/server/db.ts](../apps/web/src/server/db.ts) |

## Local Development

Nothing to install. Wrangler keeps a local SQLite file under `apps/web/.wrangler/state`.

```bash
bun run db:migrate:local
bun run dev:web
```

The placeholder `database_id` in `wrangler.jsonc` is fine locally. To start from an empty database, delete `apps/web/.wrangler/state/v3/d1` and migrate again.

Query it:

```bash
cd apps/web
bunx wrangler d1 execute DB --local --command "select id, email from user"
```

## Changing The Schema

1. Edit the Drizzle schema in `packages/features/src/db/schema/`.
2. Generate the migration: `bun run db:generate`. Commit the `.sql` file and the `meta/` snapshot together.
3. Apply locally: `bun run db:migrate:local`.

Rules that keep deploys safe (SQLite has limited `ALTER TABLE` and D1 has no migration lock):

- Additive first: new tables, nullable or defaulted columns.
- Renames and type changes go through a new column, a backfill, and a later drop.
- Never run `drizzle-kit push` against a remote database.

## Create The Remote Databases

Once per environment:

```bash
cd apps/web
bunx wrangler d1 create cloudflare-starter-develop
bunx wrangler d1 create cloudflare-starter-staging
bunx wrangler d1 create cloudflare-starter-production
```

Add `--jurisdiction eu` (or `--location <hint>`) if the data must stay in a region; it is fixed at creation. Paste each printed `database_id` into the matching `d1_databases` entry in `apps/web/wrangler.jsonc` (top level for develop, `env.staging`, `env.production`).

## Deploy Order

Apply migrations before the code that needs them:

```bash
cd apps/web
bunx wrangler d1 migrations apply DB --remote --env production
bun run deploy:production
```

Drop `--env` and use `bun run deploy` for the default (develop) environment. If the migration fails, do not deploy. D1 Time Travel can restore the database to a point in the last 30 days: `bunx wrangler d1 time-travel restore DB --env production --timestamp <iso>`.
