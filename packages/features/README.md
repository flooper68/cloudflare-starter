# @cloudflare-starter/features

The server side of the app, organised by feature. Apps (`apps/web`) are thin adapters that
call the use cases exported here. Rules and reasons: [docs/architecture/overview.md](../../docs/architecture/overview.md);
they are enforced by Biome, dependency-cruiser and `test/architecture/`.

## Layout

```
src/
├── index.ts            package root: re-exports each folder's barrel; apps import only from here
├── database.ts         composition root: every feature's tables in one schema, createDatabase()
├── queue-messages.ts   composition root: every message type on APP_QUEUE
├── kernel/             pure shared building blocks: DomainError, Clock, Ids, RequestContext
├── platform/           shared infrastructure: Drizzle client, email service, queue send, clock, ids,
│                       request context; ports/ (Logger, ErrorReporter) and adapters/<vendor>/
├── accounts/           Better Auth tables (generated) and user lookups
├── audit/              the append-only audit log: event catalog, record, list, purge
├── files/              file records and R2 storage (binding and presigned URLs)
└── greetings/          the queue and cron demo
```

A feature folder:

```
files/
├── index.ts                  public API (explicit exports)
├── files.schema.ts           its Drizzle tables (picked up by drizzle.config.ts)
├── domain/                   pure: types, zod schemas, rules, DomainErrors, with .test.ts
├── create-file-record.ts     one use case per file: one exported function, deps as first argument
└── ...
```

## Rules in short

- One use case per file; its dependencies (`db`, `clock`, `ids`, `bucket`, ...) are its first argument.
- `domain/` is pure: no I/O, no `Date.now()`, no random ids. It may import only its own domain, `kernel/` and zod.
- Folders import each other only through `index.ts`; `platform/` never imports a feature.
- Use cases throw `DomainError` subclasses; apps map them to tRPC codes or HTTP statuses in one place.
- Use cases import the `Database` type from `../database` with `import type`.
- Outside services only through a port in `platform/ports/`; vendor code and `console` only in `platform/adapters/<vendor>/`, each adapter with a contract test ([Ports and adapters](../../docs/architecture/overview.md#ports-and-adapters)).

## Adding a feature

1. `src/<feature>/` with `domain/`, `index.ts`, use-case files, and `<feature>.schema.ts` if it has tables.
2. Add the schema to `src/database.ts` and the barrel to `src/index.ts`.
3. Messages it sends on the queue go into `src/queue-messages.ts`.
4. `bun run db:generate` for new tables; `bun run lint` and `bun run test` check the structure.

## Database

- Tables: `<feature>/<feature>.schema.ts` (`accounts/accounts.schema.ts` is generated by the Better Auth CLI)
- Migrations: `migrations/` (generated SQL, applied by Wrangler from `apps/web`)

```
bun run db:generate        # write a migration from schema changes
bun run db:migrate:local   # apply pending migrations to local D1
```

See [docs/guides/how-to-setup-d1.md](../../docs/guides/how-to-setup-d1.md).
